# Stateful damage passives: native follow-up

Verified follow-up, **2026-11-02**. These 14 families now have shared passive decoding and modeled state transport for both builders. This supersedes the corresponding missing-family statements in the [earlier 477-probe report](remaining-damage-passives-verification.md); it does **not** rerun or reclassify that historical public-calculator comparison.

## Evidence and implementation boundary

Original handlers from the installed executable, SHA-256 `b8c588e46ebadbe37feca7bdf2da0ae63a8538099d14a53ec0c2241b086e5ffa`, were executed in isolated Unicorn memory. Tables, actor state and required environment services were explicit synthetic inputs; writes stayed in private emulated memory. Static callers, constructors and event writers establish lifecycle and parameter provenance separately from numeric getters. No game process, executable or save was modified. These are native executable/static checks, not fresh live combat calibration or a new external-calculator agreement claim.

The shared decoder rejects unrecognized layouts and defers missing qualified state. Raw counters remain integers until the verified float32 percentage conversion, including native epsilon. Zero-count epsilon is retained where the handler produces it. This does not establish universal bit-for-bit equivalence for every mixed modifier aggregation. Duplicate passive references are not extra instances; only explicitly transported physical occurrences receive verified instance stacking. Trigger-Happy's chance bonuses have such an occurrence proof.

## State transport and remaining limits

Fresh modeled fights initialize counters, recovery accumulators and prior-attacker lists from the proven constructors. `completedNormalAttackCount` updates after completed normal skills. `receivedAttackCountThisRound` is the API name for Heroic Nature's **received command-target count**, not visual hit count; it resets at global BeginTurn, not an Additional phase. An explicit incoming-damage scenario represents one incoming command per modeled ordinary action, rather than a recovered enemy script. Unknown mid-fight histories are not reconstructed from damage totals.

Protection state follows supported effect application and its BeginTurn/ActionBegin lifetime. Bastion queries live `DeffenceUp`-bearing members when its action is scored; it does not credit a later support cast early. Recovery power changes only after completed qualifying recovery results and uses actual clamped recipient restoration. Unsupported healing/target-history actions remain outside these represented transitions.

Runtime command provenance matters for True Stagger, Bastion, command-scoped costs and Dual Guns. Action initialization at `0x144F65329`–`0x144F6532F` overwrites owner parameter `+0x430` from action `+0x33C`, derived from the selected queued command (`entry +8`). The initial saved/menu writer alone does not prove that later selected command. The [command-route and accuracy follow-up](command-route-accuracy-verification.md) now qualifies offered roots, generic paid/Spirit/native/growth/Sync active pools, reached Awakening Vision routes and immediate wrapper/Arms parents. Paid, Spirit-granted and Sync-only actions use a proven generic route when available; they do not automatically inherit a Vision command. Missing availability/root membership still defers command-dependent terms. Versatility's independent reached-Sync count remains separate from menu-command identity.

Automatic repeats with setup rotations, luck policies, Magic Barrage, temporary Magic Boost/Reckless modifiers or unsupported support contexts remain excluded. Supported clones use native chance sampling and fresh affordability/payment checks; they are not free expected extra hits. Trigger-Happy requires qualified live target status IDs, not arbitrary debuff counts. Native status transport beyond represented fresh/support states remains incomplete.

These counts describe different bounded checks, not an exhaustive combinatorial test or new calculator comparison. Finite builder search coverage and unsupported unrelated effects remain visible in result details.

Final default recipe refinement also re-evaluates the completed physical assignment with automatic action selection. If it reveals a stronger action, one further finite assignment pass refines that recipe. This fixes the populated Sakura case where newly combined abilities made Ultima stronger than the retained Meltdown recipe. Explicit action pins and explicit small assignment budgets remain respected; no elapsed cutoff was added. Regression: `tests/final-action-reselection.test.cjs`.

The low-accuracy exclusion has been removed for supported ordinary HP-damage actions. Rapid Fire, Disorder and Deathblow now use native hit checks and matching evasion in both builders. The [command-route and accuracy follow-up](command-route-accuracy-verification.md) adds actual Amelia Rapid Fire/free Dual Guns integration, per-part stagger/critical ordering and miss-sensitive event regressions. This supersedes the earlier Fire-only integration boundary; unsupported exceptional calculation and target-nullification paths remain explicit.
